# Радиоуглеродное датирование

Тема 19: типы органических останков. Ветка `database` содержит лабораторную 2:
FastAPI, Jinja2, PostgreSQL, SQLAlchemy, Alembic, Adminer и MinIO. Без JavaScript.

Запуск из корня проекта:

```bash
source radiocarbon_dating_webapp/bin/activate
python -m pip install -r requirements.txt
docker compose up -d
python -m alembic upgrade head
python main.py
```

Настройки подключения заданы в `.env`, пример без личных данных: `.env.example`.
Для новой БД выполните `db/seed.sql` через раздел «SQL-запрос» в Adminer.
На текущем компьютере миграция и первоначальное наполнение уже выполнены.

- Приложение: http://127.0.0.1:8000/remains
- Adminer: http://localhost:8081; сервер `postgres`, база `radiocarbon_db`.
- Подробное описание, порядок защиты и SQL: [Лабораторная 2](docs/LAB2.md).
- ER-диаграмма StarUML: [radiocarbon.mdj](docs/radiocarbon.mdj).
- Просмотр ER-диаграммы: [er.svg](docs/er.svg).
- Проверка: `python -m unittest tests.test_lab2 -v`.

## Задание первой лабораторной

Цель работы: выбор варианта-темы на весь курс, знакомство с разработкой бэкенда и разработка дизайна для 3 страниц
Порядок показа: Скриншоты 1-7 Показать задание по вашей теме-варианту из списка внизу. Показать дизайн 3 страниц в Figma, показать что в приложении тоже самое. Скриншоты 8-9 Показать сайт, откуда копировали дизайн, сказать, что скопировано и в CSS это перечислить. Скриншоты 10-12 Показать три страницы приложения с поиском, при этом во вкладке Network для 3 запросов GET объяснить url: показать параметр фильтрации/поиска, а также id услуг. Скриншоты 13-17 Для страницы списка услуг показать в HTML из Response: url изображений и видео из Minio. В коде показать где эти url в коллекции услуг, а также их использование в 3 шаблонах. Скриншоты 18-19 Показать роутинг: 3 url и три контроллера для них, объяснить реализацию фильтрации/поиска.
Контрольные вопросы: MVT, компоненты MVC в лабораторной, шаблонизация, HTTP и модель OSI, Web, HTML
Задание: создание дизайна приложения в figma, базовая шаблонизация для услуг, развертывание Minio
Требуется разработать дизайн трех страниц приложения в figma, повторив при этом основную стилистику уже существующего популярного ресурса (3 цвета с точными кодами, hoover, форму карточек), связанного с вашей темой. Данные по теме также нужно искать реальные.

Создание базового интерфейса, состоящего из трех страниц. Дизайн должен быть выполнен в портретном режиме как Vibes (для мобильных телефонов). Снизу на всех страницах располагается панель вкладок с тремя пунктами навигации для трех соответствующих страниц: лента, добавление, плитка карточек. В ленте отображается короткое видео(автоматически проигрывается на странице) в вертикальной развертке и вся информация и кнопки располагаются прямо поверх видео (внизу небольшое текстовое описание с больше/меньше, остальное справа: пара полей по теме, иконка лайка с количеством, кнопка следующий). Поля по теме у каждого свои, всего 2 поля: цена, дата рейса, адрес, мощность устройства и т.д. На странице добавления повторяется та же информация, но все поля друг под другом и разделены: сверху отдельно поля для изображения и видео, ниже отдельно для текста и полей по теме. В первой лабораторной добавлять новые карточки нельзя, но можно заполнять информацию на этой странице (без сохранения). На последней странице плитка отображается список всех карточек в 2 столбца, для каждой: изображение, название, количество лайков (вычисляется по коллекции в контроллере-обработчике) одно поле для фильтрации по теме. При клике по карточке происходит переход на страницу ленты начиная с этой карточки.

Для каждой услуги указывается один из 3 статусов: черновик, опубликован, удален. В коллекции должна быть одна услуга в статусе черновик, именно она отображается на странице добавление. Услуги в статусе удален в интерфейсе не отображаются. На странице плитка добавить поле input для фильтрации на сервере списка услуг по одному из полей по теме (цена, масса, дата события, но не текстовое поле), отображаемых на странице (по умолчанию отображать все). Поле поиска должно сохраняться после запроса.

Всего в приложении должно быть 3 GET запроса (лента по ID, получение черновика, список всех карточек) и одна модель-коллекция. Все данные для страниц нужно брать прямо из коллекции (массива услуг с вложенными лайками ID пользователей), без использования БД. Никаких массивов внутри отдельной услуги для полей по предметной области (соблюдать атомарность и 1НФ), можно писать только текстовые описания, даты, числа. Никакого редактирования, только поиск и просмотр. Метод GET ленты по ID услуги открывает ее страницу, если указан второй параметр ?next=true, то открывается следующая услуга после этого ID, для панели вкладок ID не указывается. Без JavaScript

В приложении должны быть использованы стили, для каждого элемента списка подгружается свое изображение. Изображения услуг отображатся на всех трех страницах. Изображения и видео хранятся в Minio, наименование изображения и видео указано ключом на латинице, хранятся в модели двумя отдельными полями. Разработать стиль приложения, который будет применяться далее в последующих лабораторных по фронтенду. CSS вынести в отдельный файл. Minio установить по методичке в Docker Desktop или для Linux с Portainer
